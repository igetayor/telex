📐 Worker Pool Architecture & Concurrency Pipeline

Telex separates message ingestion from concurrent payload execution using a bounded channel architecture. A consumer pulls from RabbitMQ (with QoS prefetch) or an event stream, and feeds into a fixed pool of worker goroutines.

Retry Policy & Exponential Backoff

When a transient error occurs, Telex applies Full Jitter Exponential Backoff: 

delay = min(max_backoff, base_backoff * factor^(attempt - 1))
jittered_delay = (delay / 2) + rand(0, delay / 2)

This ensures that failed tasks don't synchronize into thundering-herd spikes when recovering downstream services.
